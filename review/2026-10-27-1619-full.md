## Summary

The read-only client, statistics and archive preview preserve the reviewed
account-safety boundaries. Production requests are GET-only, credentials
stay in the browser evaluation, and listing failures cannot produce a
partial preview or statistics summary. Archive apply and undo still exit
nonzero without invoking a transport; no manifest implementation exists.

All three earlier findings are fixed and their original failure scenarios
were rerun. One new P3 input-validation defect remains: deeply nested
exclusion patterns escape argparse as a regex compiler recursion error.
No P0, P1 or P2 defect was confirmed. No live account was accessed.

## Invariants

- Account mutation requires explicit `--apply` and a fixed, persisted
  manifest before the first change. These are future integration gates;
  the current implementation exposes no mutation transport.
- Only a present, null `gizmo_id` permits selection. A non-null
  `conversation_template_id` also blocks selection; absence of that
  second field is the documented exception. Archive state must be
  exactly boolean false.
- IDs selected for archiving contain only ASCII letters, digits, `-`
  and `_`. Every observed copy of an ID must pass independently; one
  unsafe copy withdraws an earlier selection.
- Selection and rendering read no clock or external state. The CLI fixes
  its relative cutoff before fetching. Cutoffs are timezone-aware and
  strict; selected and skipped counts account for every received row.
- Production pagination preserves raw fields and duplicate IDs, checks
  each response's offset/limit/total, and uses the current page's total.
  Exhaustion, malformed envelopes and page limits fail the whole walk.
- Raw listing JSON crosses the browser boundary as text; strict Python
  decoding rejects duplicate keys at every depth before selection.
- All page-script requests use GET-only helpers. Origin and explicit tab
  target checks precede listing access; credentials stay inside the page.
  Retries and delays are bounded and ordinary requests are sequential.
- Statistics describe observations from separate listings, never an
  authoritative account total. Conflicting duplicate categories become
  unknown; archive output escapes untrusted titles on one terminal line.
- Diagnostics omit arbitrary response bodies and subprocess output.
  Probe error messages must not bypass report redaction. User argument
  conversion failures should become usage errors without tracebacks.
- Each required test suite must pass at least one declared test case.
  Staged-file hooks validate the index without rewriting source.

## Findings

### Open and Moved

- `regex-nesting-recursion` — **Deeply nested exclusion patterns bypass CLI validation.** Bug · Open · Verified.
  - Where: `chatctl/cli.py:38` (`_regex` exception handler).
  - Severity: P3.
  - An exclusion pattern containing 500 nested groups makes `re.compile`
    raise `RecursionError`, which the handler does not convert into an
    argparse error. A synthetic subprocess exits 1 with a traceback and
    empty stdout before contacting the transport. Handle this compiler
    failure alongside `re.error` and `OverflowError`; test usage exit 2,
    no traceback and no transport calls. This affects local input
    handling, with no demonstrated account-safety impact.
  - Review backlog: `handle-regex-recursion`

Reproduction, from the repository root; no browser access occurs:

```python
import subprocess
import sys

result = subprocess.run(
    [
        sys.executable,
        "-m",
        "chatctl",
        "archive",
        "--target",
        "synthetic-tab",
        "--before",
        "2026-01-01",
        "--exclude",
        "(" * 500 + "a" + ")" * 500,
    ],
    capture_output=True,
    text=True,
)
print(result.returncode, result.stderr.splitlines()[-1])
```

Run the block with `uv run --locked python`. Observed result:
`1 RecursionError: maximum recursion depth exceeded`.
