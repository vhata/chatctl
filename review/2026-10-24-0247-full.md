## Summary

The implemented selection and CLI skeleton preserve the current account
safety boundaries. All three commands intentionally exit non-zero without
performing work; no archive, undo, manifest or live transport implementation
exists on the reviewed main commit. Selection rejects uncertain membership
and withdraws an eligible conversation if a conflicting duplicate appears.

Three defects remain: project-probe errors can copy arbitrary exception
text into the report, empty JavaScript test files satisfy the nonempty
suite gate, and oversized regex repetitions produce a traceback rather
than a CLI usage error. All were reproduced with synthetic inputs. No P0
or P1 finding was confirmed, and no reproduction used a real account.

## Invariants

- Account mutations require explicit `--apply`, and must use a complete,
  persisted manifest before the first change. These remain requirements
  for future code; current commands are stubs.
- Only a present, null `gizmo_id` permits selection. A non-null
  `conversation_template_id` also blocks selection; its absence is the
  documented exception. Archive state must be exactly boolean false.
- A selected ID uses only ASCII letters, digits, `-` and `_`; all copies
  of that ID must independently pass selection. Malformed metadata is a
  skip reason, never an eligibility default.
- Selection reads neither the clock nor external state. Cutoffs and
  timestamps used for selection are timezone-aware, the boundary is
  strict, and output preserves input order without modifying inputs.
- Discovery requests remain sequential GETs through `makeGet`. Pagination
  uses each page's current total, advances by received page length and
  terminates on errors, repeated pages or the page cap.
- Report privacy applies to error paths as well as successful payloads.
  Arbitrary exception messages must not become report content.
- User input rejected during argument conversion must produce a usage
  error rather than an uncaught implementation exception.
- Every baseline suite must pass at least one test. Staged-file hooks
  must validate staged content without rewriting the worktree.

## Findings

### Open and Moved

- `probe-exception-text-disclosure` — **Project-probe errors bypass report redaction.** Security · Open · Verified.
  - Where: `discovery/probe.js:359` (`runProbe`), specifically line 363;
    called for the projects endpoint at line 393.
  - Severity: P2.
  - `runProbe` writes `String(error)` verbatim into the downloaded report,
    while `walkList` deliberately records only an error type because
    messages may contain URLs or response text. A synthetic wrapped fetch
    that rejects the projects request with a private-text marker puts the
    complete marker in `report.probes.projects.error`. Use the existing
    error-type-only handling consistently and cover rejected project
    requests with a privacy regression test; this is not evidence that
    native browser failures currently expose account data.
  - Review backlog: `redact-probe-errors`

- `node-empty-file-counts-as-test` — **Empty discovery test files pass the required test gate.** Tooling · Open · Verified.
  - Where: `scripts/test.sh:45` (Node TAP pass-count check), lines 45–47.
  - Severity: P2.
  - Node counts an import-only test file as one passing file wrapper,
    so replacing every JavaScript test with only
    `const test = require("node:test");` still produces `# pass 1` and
    exits zero through the required gate. A disposable copy of the real
    project test script with one passing pytest test and that empty Node
    suite reproduced this with real uv and Node 26. Distinguish executed
    test cases from file-wrapper success and add an empty-file regression
    when enforcing the documented nonempty-suite policy.
  - Review backlog: `reject-empty-node-tests`

- `regex-repetition-overflow` — **Oversized regex repetitions bypass CLI validation.** Bug · Open · Verified.
  - Where: `chatctl/cli.py:26` (`_regex`), specifically lines 28–29.
  - Severity: P3.
  - `uv run --locked chatctl archive --older-than 90d --exclude
    'a{4294967295}'` raises `OverflowError: the repetition number is too
    large` instead of the documented argparse usage error. `_regex`
    catches `re.error` only; catch repetition overflow as another invalid
    pattern and extend the regex validation tests.
  - Review backlog: `handle-regex-overflow`
